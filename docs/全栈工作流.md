## 1. 架构总览

| 层 | 内容 | 位置 |
| --- | --- | --- |
| 静态页面 | 14 个根目录 HTML + `assets/`（CSS/JS/数据生成物） | 仓库根、`assets/` |
| 边缘函数 | Pages Functions：账号、档案、题库平台、AI 批改/教练、短信 | `functions/api/`（路由薄封装）+ `functions/_lib/platform.js`（实现） |
| 数据库 | Cloudflare D1 `kaoyan-atlas-accounts`：users / sms_send / codes / login_fail / user_profiles / user_notes / platform_*（首次调用自动建表，含 platform_subjects） | wrangler.toml 绑定 `DB` |
| 对象存储 | R2 `kaoyan-atlas-library`：资料库文件与笔记附件 | wrangler.toml 绑定 `LIBRARY_FILES` |
| AI 通道 | 单一 OpenAI 兼容通道（文字+识图共用）：`platform.js` 的 `ai()`，环境变量 `AI_BASE_URL` / `AI_API_KEY`(或 `DASHSCOPE_API_KEY`) / `AI_MODEL`；默认值写在 wrangler.toml `[vars]`：`https://maas.qianwenaiapi.com/compatible-mode/v1` + `qwen3-vl-plus` | `functions/_lib/platform.js` |
| 批改执行 | 阿里云 ECS（深圳）上的 atlas-worker：轮询站点 claim 接口领取待批改 attempt（先到先批、并发 3 题/2 卷、单模型 60 秒超时、模型链见 platform.js 的 ai.routing），回写结果；Functions 只负责入队与发结果。运维走阿里云云助手通道，代码在 ECS `/opt/atlas-src` | ECS `atlas-worker.mjs` |
| 内容源 | 题库源 JSON、章节题、笔记源、词汇源 | `src/bank/`、`src/chapters/`、`lazy-src/`、`src/` 其余 |
| 生成物 | `assets/questions.js`（整站题库 6,056 题，运行时按科目拆 7 分片按需加载）、`assets/lazy-*`、`assets/daily-data.js`（每日一题题池）、`assets/catalog/`（院校目录 932 分片）、`functions/_lib/import-prompt.js` 等 | 必须随源一起提交（Pages 构建不跑 Python） |

## 2. 本地开发

环境：Node ≥ 18、Python 3（本机用 `py -3`，其他机器用 `python3`）。

```bash
npm run check            # 全仓自检：JS 语法 + 题库 JSON + 页面登记（scripts/check.mjs）
npm run build            # Pages 构建演练：生成 dist/（含 import 技能与笔记库转换）
npm run build:questions  # 改题库源后重建 assets/questions.js
npm run dev              # npx wrangler pages dev .（本地跑 Functions + D1 模拟）
npm run test:backend     # 后端回归（Node 24；门禁/批改租约/分值/注销/API）
npm run release          # 发布前组合：check + build
```

日常改动流程（与 AGENTS.md 一致）：拉最新 master → 开主题分支 → 改 → `npm run check` →
后端改动加跑 `npm run test:backend` →（如动了题库源）`npm run build:questions` → push 分支开 PR → 合并后自动部署。
紧急修复可直推 master，但必须先过 `npm run check`；涉及后端时还要过 `npm run test:backend`，并在提交信息里写清原因。

## 3. 构建与部署流水线

1. **GitHub Actions `validate`**（`.github/workflows/validate.yml`）：push/PR 时并行运行全仓自检/构建演练与 Node 24 后端回归，任一失败都不要合并。
2. **GitHub Actions `build-questions`**：master 上 `src/bank/**`、`src/chapters/**` 变更时自动重建 `assets/questions.js` 并回提交（提交信息带 `[skip actions]` 防循环）。因此改题库源时可以不再手工提交 questions.js——但 PR 阶段它仍是旧版，预览部署里看不到新题，合并后自动补齐。
3. **Cloudflare Pages**：master 推送后自动执行 `node scripts/build-pages.mjs`，把登记的页面与 `assets/web/content/pdf` 复制到 `dist/` 发布；其他分支生成预览部署。
   - ⚠ **新页面必须登记**：`build-pages.mjs` 的 `FILES` 是白名单，未登记的根目录 `.html` 不会进 dist（线上 404）。构建脚本与 `check.mjs` 都会对此报错拦截。2026-11-15 的 `analytics.html` 就漏登记过一次，见 CHANGELOG。
   - `build-pages.mjs` 还会顺带重跑 import 技能提示词生成与笔记库转换，所以 `skills/import-questions/SKILL.md`、`lazy-src/` 的改动在构建时自动生效，仍需提交源文件。
4. **环境变量**：只在 Cloudflare 控制台维护（`SESSION_SECRET`、短信、`DASHSCOPE_API_KEY`、可选 SMTP）；`AI_BASE_URL` / `AI_MODEL` 在 wrangler.toml `[vars]`。仓库不放密钥。本地若要接 localhost 自选 AI，显式设置 `ALLOW_LOCAL_AI=1`；生产不要开启。
5. **上线验收**（每次部署后）：
   - `GET /api/health` 返回 ok 且 `ai.key=true`、`smsDevCode=false`、D1/R2 绑定为 true；
   - 未登录访问 `/login`/`/register` 样式完整；`/api/auth/me` 对旧 token 返回空用户；
   - 登录后抽查：首页图谱、刷题提交一次批改、套卷分析、资料库列表、AI 向导各点一次；
   - 同时观察浏览器批改与 ECS worker，确认同一题未重复调用 AI；
   - 新页面直接访问不 404。

## 4. 数据与内容流水线

- **内置题库**：`src/bank/imported-*.json`（`{"items":[...]}`，选项写在 text 内）+ `src/chapters/*/ *.json` 章节题 → `src/build/build_questions.py` 按 id 去重合并 → `assets/questions.js`（`window.QUESTIONS`）。个人题不在此列，走 D1 `platform_questions`。
- **导入新题**：优先用站内资料库的「上传 → 抽题 → 审阅 → 导入」闭环；批量灌库用 `skills/import-questions` 规范（逐题转写、逐题自解核对、存疑单列），脚本在 `src/build/` 有历年导入脚本可参考。导入后必跑 `npm run check` 看缺答案/缺解析统计。
- **答案与解析质量**：客观题批改会与参考答案强制对分，答案错误会污染批改——改答案必须附依据并记入当期 CHANGELOG/勘误文档（例：`docs/audit/` 与 2026-11-15 数二勘误）。
- **题库全量校核（2026-11-15 已完成一轮）**：方法固定为「独立判答/重解在先，与题库 stored answer 对照；不一致时以官方答案或多来源按**答案文本**（不按字母，各版本选项顺序不同）裁定；存疑项单列 flag，绝不强行改」。本轮结果：807 勘误 44 处、数二 2 处、英语一答案改正 135 处、英语二补缺 311 题、肖1000 补全 241 题并去重，全库占位清零；逐科文档在 `docs/audit/2026-11-15-*.md`。后续新增年份真题按同一方法先校核再入库。
- **院校专业目录（已全量上线）**：档案选择器走静态分片目录 `assets/catalog/`（研招网 2027 全国目录，共 932 个分片、约 24MB，已随仓库部署；抓取器在仓库外 `~/workspace/catalog-crawl`，用院校库枚举校名 + zsml 全名回查权威记录、只取第一页并按分类/标志切分绕开登录翻页限制；`build_shards.py` 生成分片），个别分片缺失时才回退 `functions/_lib/programs.js` 的站内精选目录（手工维护、逐条核查，绝不凭记忆编组合）。
- **每日一题题池**：`python3 scripts/build-daily.py` 从 `src/bank/` 抽独立客观单选题（无原文、四选项齐全、含解析），按真题优先/年份新者优先/知识点轮转分层抽样生成 `assets/daily-data.js`（数一/二/三、政治各 60 题）；题库源更新后重跑脚本并随代码一起提交，前端按档案 variants 选池。

## 5. AI 子系统

- **批改** `POST /api/grade`：`functions/_lib/prompts.js` 按学科选系统提示词（`gradeSystemFor`），先转写后批改两段式处理手写照片；分数越界钳制不抛错；客观题与参考答案不一致时以参考答案复核；作文走 `essaySystem`。分值推断只在 `functions/_lib/scoring.js`。
- **结果缓存**：批改结果存 D1 `platform_results`，同一 attempt 已批改的题直接返回缓存——**改提示词后旧 attempt 不会重批**，验证效果要用新作答。
- **教练** `POST /api/coach`：默认人设为学习指导老师，并从个人题库检索最多 3 条相关资料；当 `context.source === 'home-guide'` 时切换为首页向导人设 `GUIDE_SYSTEM`（含站内地图），走真实多轮消息，用户消息可带 `images`（data URL，≤3 张，服务端校验格式与大小）。
- **换 AI 服务**：只改 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 三个变量，必须选同时支持识图的模型；`ai()` 对只写了域名、没带 `/compatible-mode/v1` 路径的 `AI_BASE_URL` 有自动补全兜底，但不要依赖它，常态写完整路径。
- **故障定位顺序**：先 `GET /api/health` 看 host/model/key → 再用同一 key 直连上游 `/chat/completions` 自测 → 上游正常而站内失败，多半是某个具体流程（把站内报错原文发给维护者定位），不要先动 key。

## 6. 常见故障速查

| 现象 | 先查 |
| --- | --- |
| 新页面 404 | 是否登记进 `build-pages.mjs` 的 FILES |
| AI 全部不可用 | /api/health 的 ai 字段；上游直连自测；AI_BASE_URL 是否完整路径 |
| AI 全部不可用且 health 正常、上游直连偶尔能通 | 查上游账户欠费/停服通知：百炼欠费会直接停服（2026-11-15 出现过欠费 0.18 元停服的短信实例），结清并小额充值后用新作答复测 |
| 批改改了提示词没变化 | 旧 attempt 命中缓存，用新作答验证 |
| 短信收不到 | health 的 smsMode/smsMissing；阿里云 PNVS 配置 |
| 登录页出现演示验证码 | 生产环境不应出现（smsDevCode 应为 false），出现即查环境变量 |
| 部署没生效 | Pages 构建日志是否红（多半是 build-pages 校验拦截）；分支是否为 master |

## 7. 升级配方（后续迭代照此办理）

- **加一个页面**：写 `xxx.html` + `assets/xxx.css/js` → 登记 FILES → 如需全站视觉，接 `assets/theme.css` 并用统一页眉 `.top` → `npm run check` → PR。
- **加一个内置科目（现状：散点多，慎改）**：2026-11-21 多学科结构审计（`~/workspace/kaoyan-audit/多学科结构调研与本站方案-2026-11-21.md`，工作区文档）实测新增一科要改 15+ 处：platform.js 科目集合与名称表（全站名表重复 ≥11 份）、scoring.js 分值、practice.js 组卷配额与板块序、analytics 分科维度、prompts.js 分科指令、题库分片前缀、各前端 SUBJECTS 列表等，漏改会静默降级（如未知科目分值回退按数学表算）。目标方案是科目注册表 `src/subjects.json` 单一事实源 + `resolveSubjects(profile)` 唯一派生函数：冻结前（2026-12-15 前）只落注册表与生成脚本、不接线；考后分三阶段收敛。在收敛完成前，加科目前必须按审计报告的散点清单逐项核对，并跑 check 与 build:questions。
- **扩院校目录**：按 §4 目录规则分校批次提交，每批在 CHANGELOG 记来源与核查范围。
- **改批改标准**：只改 `prompts.js` / `scoring.js`，用新作答回归 3–5 道典型题（含一道路照片题）再合并。
- **视觉迭代**：令牌只改 `theme.css`；页面专属样式留在各自 CSS；保持页眉高度 `--header-h` 与品牌区一致，避免跨页跳动。
- **性能路线**：题库分片懒加载已实施（2026-11-20：构建拆 7 分片、questions-loader 按需加载，错题本/复盘入口按题目 id 只加载涉及科目分片，大题量批改详情按卡懒渲染）；`_headers` 已给静态资源 stale-while-revalidate，新增资源记得带 `?v=` 版本号。后续备查：分片内容指纹版本号、KaTeX 懒加载（已由 AtlasKatex 按需加载实现）。
- **后端性能（2026-11-22 已实施）**：platform.js 建表 DDL 改为每 isolate 只跑一次（platformSchemaReady 标志，与 db.js 同口径）；答题记录列表由逐条 2N 次查询改为两次批量查询后内存组装（返回结构不变）；教练问答检索 retrieveContext 改用 json_extract 只投影 text/answer/kpName/chapterTitle 四个字段，不再整表读全量 JSON 逐条 parse；词汇页状态保存加 600ms 去抖合并（关页/切后台时立即补发）。三项后端改动均有 node:sqlite 实测 harness 验证（建表批次数、列表组装字段、教练参考命中）。

## 9. 后端可靠性收口（2026-11-22）

本轮只改后端、测试与 CI，不动前端。详细报告见 `docs/backend-optimization-2026-11-22.md`。

- 中间件私有路径改为 fail-closed；D1 异常返回 503，公开路径与登录页资源继续放行。
- 会话令牌增加 `sv` 版本；旧 token 按 0 兼容，改密后其他设备立即失效，当前设备换发新 token。
- 注销补全社区表、点赞/评论关联数据和 R2 的 `library/uid/`、`uid/`、`uid-` 三类键；社区导入文件只删除自己的记录，不删除他人的 R2 原对象。
- 自带 AI 配置新增 24 小时 TTL；attempt 响应不回显密钥。
- ECS worker claim 使用 `data` 原值 CAS；单题批改使用 `platform_grading_claims` 租约，浏览器与 worker 不会重复调用 AI。
- `allocatePaperDetailed()` 提供分值诊断；显式分值超过科目总分时接口返回 400。
- CI 新增 Node 24 后端回归 job；`validate` 和 `build-questions` 均增加 concurrency。

上线后重点抽查：登录页样式、两台设备改密、交卷批改只出现一次、注销后社区和 R2 残留、超总分卷面被拒。
