## 二、⚠️ 挂网风险（重要，请先看这条）

### 好消息：成品已经全部在 git 里

`git show HEAD:assets/questions.js` 实测结果：

- 807 题数 **193**、全库 **4662 题**，与工作区**完全一致**。
- 抽查勘误已全部进入 HEAD：`807-2005-1`(D)、`807-2008-8`(7 度)、`807-2013-8`(中柔度)、
  `807-2015-1`(132.6)、`807-2016-2`(69.14) 全部命中。
- 新年份 `807-2020-1`、`807-2024-1`、`807-2026-1` 均存在。
- `git status` 除备案文档外为 clean。

**结论：挂网显示不会有问题，网页上能看到全部 22 套卷、193 题。**

### 但有个隐患：`.gitignore` 的 `bank/` 误伤了 `src/bank/`

`.gitignore` 第 2 行是：

```
bank/
```

git 的这条规则**会匹配任意层级的 `bank` 目录**，因此 `src/bank/` 也被忽略了。

实测结果：

| 检查项 | 结果 |
|---|---|
| `git ls-files src/bank/ \| wc -l` | **0**（一个都没跟踪） |
| `src/bank/*.json` 实际文件数 | **153** |
| `git check-ignore -v src/bank/imported-807-2020.json` | 命中 `.gitignore:2:bank/` |

**后果**：

- 网页本身能正常显示（因为 `assets/questions.js` 这个**成品**在 git 里）。
- 但**源数据 153 个 JSON 全都不在仓库里**。将来在新机器/新克隆上跑
  `py -3 src/build/build_questions.py` 重建，题库会变成**空的或只剩章节题**。
- 也就是说：**挂上去的是成品，配方没进仓库。**

### 建议的修法（需要你决定，我没有擅自动）

在 `.gitignore` 里把 `bank/` 改成只忽略根目录：

```diff
- bank/
+ /bank/
```

这样 `src/bank/` 会被正常跟踪，而根目录的 `bank/`（几百 MB 的 PDF）继续忽略。

改完后需要：

```bash
git add -f .gitignore
git add src/bank/          # 153 个 JSON，约 3MB
git commit -m "fix: track src/bank data files (gitignore bank/ over-matched)"
```

**在挂网完成前做还是之后做，由你定**——现在不做也不影响网页显示，只影响“以后能不能重建”。
