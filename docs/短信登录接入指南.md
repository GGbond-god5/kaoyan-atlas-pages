# 短信验证码注册登录 · 接入与部署指南

面向「考研科目大观」：前端静态站点部署在 Cloudflare Pages，后端（短信验证码 + 账号服务）跑在阿里云 ECS。

先说最重要的一件事，它能省掉你至少一周的来回审核。

## 一、学生个人账号不要申请传统短信签名

传统「短信服务」的国内签名，必须关联资质并完成运营商实名报备。阿里云官方文档的说法是：**个人账号的自用资质无法通过签名实名制报备**，个人用户应改用「短信认证」产品或升级企业认证。

也就是说，用学生个人实名认证的账号去申请签名，大概率卡在审核或报备环节，报备还要 5–7 个工作日。

你要用的是同一控制台里的另一条通道：**号码认证服务（PNVS）→ 短信认证**。它 2025 年 11 月上线，个人实名认证即可开通，**免资质、免签名申请、免模板申请**，阿里云赠送一套签名和标准模板（登录/注册 100001、修改绑定手机号 100002、重置密码 100003、绑定新手机号 100004、验证绑定手机号 100005）。验证码多长、几分钟有效、能不能重复发，都由参数控制。

代码里这两条通道都实现了，用 `SMS_PROVIDER` 切换：

| 值 | 通道 | 适合谁 | 验证码由谁生成 |
| --- | --- | --- | --- |
| `pnvs` | 号码认证服务 · 短信认证 | **个人 / 学生（推荐）** | 阿里云生成，阿里云核验 |
| `dysms` | 短信服务 Dysmsapi | 已企业认证，需要自定义签名文案 | 本地生成，本地比对 |
| `mock` | 不发短信 | 本地开发 | 本地生成，打印在控制台 |

赠送签名和赠送模板必须配套使用，不能拿赠送签名配自定义模板，反过来也不行。

## 二、开通短信认证（约 10 分钟）

1. 阿里云账号完成**个人实名认证**。
2. 打开「号码认证服务」控制台，开通**短信认证**和**融合认证**功能。
3. 在「短信认证」页面找到**赠送的签名名称**和**模板编号**，记下来。签名文案是固定的，模板 100001 就是登录/注册场景。
4. 创建 RAM 子账号：控制台右上角 → 访问控制 RAM → 用户 → 创建用户，勾选「OpenAPI 调用访问」，拿到 **AccessKey ID / Secret**（Secret 只显示一次）。
5. 给这个子账号授权 `AliyunDypnsFullAccess`。**不要用主账号 AccessKey**，主账号 AK 泄露等于整个阿里云账号被接管。

费用方面：发送失败不计费，核验免费。按条计费，通常几分钱一条，可以先买 1000 条的小套餐包试水。你那张 300 元学生券能不能抵扣，取决于券的适用产品范围（券一般只覆盖 ECS、RDS 这类指定产品），在控制台「费用与成本 → 优惠券」里能看到适用范围，别默认它能付短信费。

## 三、配置后端

```bash
cd server
cp .env.example .env      # Windows: copy .env.example .env
npm install
```

编辑 `server/.env`，最少填这四项：

```ini
ALIYUN_ACCESS_KEY_ID=LTAI5t********
ALIYUN_ACCESS_KEY_SECRET=************************
ALIYUN_SMS_SIGN_NAME=控制台赠送的签名名称
SMS_PROVIDER=pnvs
```

模板编号留空就用赠送的 100001。前两项或签名没填时，服务会自动退回 `mock` 模式，验证码打印在服务端控制台，方便先把页面跑通。

```bash
npm start
```

打开 `http://127.0.0.1:3000/login.html`。第一次启动会打印一行提示，告诉你当前是 `mock` 还是 `pnvs`，以及数据文件位置。

想确认配置有没有生效，访问 `http://127.0.0.1:3000/api/health`，它会告诉你当前通道、是否配置完整、还缺哪些环境变量。

## 四、页面与接口

新增文件：

```
login.html            登录页（密码登录 / 验证码登录 / 已登录面板）
register.html         注册页（手机号 + 短信验证码 + 昵称 + 密码）
assets/auth.css       账号页样式，沿用大观的纸感配色与衬线排版
assets/auth.js        接口封装、令牌、验证码倒计时
assets/auth-nav.js    顶栏「登录 / 昵称」入口
server/               Express 后端
.assetsignore         Cloudflare Pages 部署时排除后端目录
```

`index.html` 顶栏加了账号入口，已登录时显示昵称，点进去能看到注册时间和最近登录时间，可以退出。

接口一览：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/sms/send` | 发送验证码，body `{phone, scene}`，scene 为 `register` 或 `login` |
| POST | `/api/auth/register` | 注册，body `{phone, code, nickname, password}` |
| POST | `/api/auth/login` | 登录，`{phone, password}` 或 `{phone, code}` |
| POST | `/api/auth/logout` | 退出 |
| GET | `/api/auth/me` | 当前用户，未登录返回 `{user: null}` |
| POST | `/api/grade` | 原来的 AI 评卷，已从 serve.py 移植过来 |
| GET | `/api/health` | 自检 |

用 curl 走一遍（`mock` 模式下 `devCode` 会直接返回）：

```bash
curl -s -X POST http://127.0.0.1:3000/api/sms/send \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13800138000","scene":"register"}'
```

## 五、部署到 Cloudflare Pages + 阿里云 ECS

这里有个容易踩的坑：**Cloudflare Pages 的域名和 ECS 的域名不同源，跨站 Cookie 会被现代浏览器拦掉**。所以代码里做了两条路，`assets/config.js` 的 `apiBase` 决定走哪条。

### 推荐：同一个主域名，Cookie 方案

把前端挂到 `www.your-domain.com`（Cloudflare Pages 自定义域名），接口挂到 `api.your-domain.com`（ECS + Nginx + Cloudflare 代理）。两者同属一个可注册域，SameSite=Lax 的 Cookie 正常工作，前端 `apiBase` 填 `https://api.your-domain.com`，`CORS_ALLOW_ORIGIN` 填 `https://www.your-domain.com`。

### 临时：pages.dev + ECS，令牌方案

前端还是 `kaoyan-atlas.pages.dev`，接口是 `https://api.your-domain.com`。这时跨站 Cookie 不可靠，前端会自动改用 `Authorization: Bearer` 令牌（登录/注册接口同时返回 token，存在 localStorage，7 天过期）。服务端已经同时接受 Cookie 和 Bearer，不用改代码。

### ECS 上跑起来

```bash
# ECS 上装 Node 18 以上
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -   # CentOS/Alibaba Cloud Linux
sudo yum install -y nodejs

# 传代码（rsync / scp / git），然后
cd /opt/kaoyan-atlas/server
npm install --omit=dev
cp .env.example .env && vi .env
```

`.env` 里线上要改这几个：

```ini
NODE_ENV=production
PORT=3000
HOST=127.0.0.1            # 只监听本机，由 Nginx 对外
TRUST_PROXY=1
COOKIE_SECURE=1
CORS_ALLOW_ORIGIN=https://kaoyan-atlas.pages.dev
SESSION_SECRET=用 openssl rand -hex 32 生成一串
```

用 pm2 常驻：

```bash
sudo npm i -g pm2
pm2 start index.js --name kaoyan-api
pm2 save && pm2 startup
```

Nginx 反代（顺便把接口也上 HTTPS，否则浏览器会拦截 http 接口）：

```nginx
server {
    listen 443 ssl http2;
    server_name api.your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/api.your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.your-domain.com/privkey.pem;

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

ECS 安全组放行 443（不要放行 3000，让它只在本机）。域名解析到 ECS 公网 IP 之前，国内节点要求域名完成 **ICP 备案**，没有备案的话 80/443 会被拦；这段时间可以先用 Cloudflare 代理的 pages.dev 域名加 ECS 的 IP 直连测试。

### 发到 Cloudflare Pages

仓库根目录已经有 `wrangler.toml`（`pages_build_output_dir = "."`），我另加了一份 `.assetsignore`，把 `server/`、`data/`、`docs/` 排除在外——否则你的 `.env`、AccessKey 和 `node_modules` 会一起被上传到 Cloudflare，这是很典型的泄露事故。

```bash
npx wrangler pages deploy .
```

部署后在 `assets/config.js` 把 `apiBase` 改成 `https://api.your-domain.com`，重新部署一次。前端是纯静态，改完刷新即可生效。

## 六、安全上已经做了什么

密码用 scrypt 加盐哈希，不存明文；验证码 5 分钟过期、错误 5 次作废、同号码 60 秒一条、单号码每天 10 条、单 IP 每天 20 条；密码连错 5 次锁 10 分钟；会话是 HMAC 签名的令牌，Cookie 带 HttpOnly 和 SameSite=Lax，线上自动加 Secure；`NODE_ENV=production` 时 `/server`、`/src`、`/content`、`/data` 这些目录一律 403；日志里手机号打码，验证码不进日志。

还没做的，按需再加：图形/滑块验证码（挡住脚本刷接口）、重置密码流程（模板 100003 就是干这个的）、把 JSON 文件换成 MySQL 或 SQLite（用户上千以后再考虑）、邮箱或微信绑定。

## 七、想用官方 SDK 的话

现在用的是手写 RPC 签名，只依赖 `crypto` 和 `fetch`，少一个依赖也少一次装包失败。如果导师要求用官方 SDK：

```bash
npm i @alicloud/dypnsapi20170525 @alicloud/openapi-client
```

```js
const Dypnsapi = require('@alicloud/dypnsapi20170525');
const { Config } = require('@alicloud/openapi-client');

const client = new Dypnsapi.default(new Config({
  accessKeyId: process.env.ALIYUN_ACCESS_KEY_ID,
  accessKeySecret: process.env.ALIYUN_ACCESS_KEY_SECRET,
  endpoint: 'dypnsapi.aliyuncs.com',
}));

await client.sendSmsVerifyCode(new Dypnsapi.SendSmsVerifyCodeRequest({
  phoneNumber: '13800138000',
  signName: '控制台赠送的签名',
  templateCode: '100001',
  templateParam: JSON.stringify({ code: '##code##', min: '5' }),
  codeLength: 6,
  validTime: 300,
  interval: 60,
}));
```
